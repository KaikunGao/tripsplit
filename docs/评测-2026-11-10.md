# 录入解析评测：20 → 100 例、三模型横评、一轮 badcase 修复（2026-11-10）

## 为什么做

简历里「模型选型 / 成本质量 trade-off」「评测维度 / 高频 badcase / 优化前后」两处要填真实数字。做法按「理想态 → 评测维度 → 评测集 → 最高频 badcase → 修 → 看有没有回退」走一遍。

## 评测维度

- 字段维度 7 个：入账决策（auto / ask / reject）、金额、付款人、参与人、分类、请客、币种。一例全部字段都对才算通过。
- 效率维度 2 个：单条耗时、单条成本（按官方价目由 token 数折算，含缓存读写）。
- 用例维度：每例打 `tags`，共 30 类表达方式（中文数字、需计算金额、多金额候选、付款人缺失 / 别称 / 非成员 / 多人付、参与人全员 / 子集 / 排除 / 缺失、请客、个人消费、外币、分类边界、非消费、语音转写噪声、一句两笔、押金、时间等）。

## 评测集

- v1：20 例（2026-11-04）。v2：100 例（2026-11-10），t01–t20 原样保留，c21–c100 新增。
- **全部构造**：线上遥测 `runs` 表只存录入方式与决策、不存原文，而且截至今天没有一条 `extract` 调用（只有 1 条核账、1 条语音），没有线上原文可抽。构造按旅行记账的说法分层，决策分布 74 auto / 18 ask / 8 reject，89 文字 / 11 语音转写。
- 标注原则：参与人、付款人要有文字依据，没有就 ask，不按「4 张票 = 4 个人」推断（沿用 v1 t04 的口径）。c41 起初标成 auto 全员，与此冲突，在基线跑完后改为 ask；下表的 before 数字都已按改后的标注重算。

## 结果（100 例，同一提示词三模型；before = 旧提示词，after = 补了请客等规则）

| 模型 | before 通过 | after 通过 | after 原 20 例 | 100 例成本 | 单条成本 | 单条耗时 |
|---|---|---|---|---|---|---|
| claude-opus-5-5 | 92 | **96** | 19/20 | $6.91 | 6.9 美分 | 2.8 s |
| claude-sonnet-5-5 | 90 | **97** | 20/20 | $1.29 | 1.3 美分 | 1.7 s |
| claude-haiku-5-5 | 84 | **88** | 19/20 | $0.55 | 0.55 美分 | 3.8 s |

after 的字段准确率（sonnet）：决策 98/100、金额 87/87、付款人 83/84、参与人 81/81、分类 84/85、请客 100/100、币种 8/8。

**模型选型结论**：在这套评测集上 sonnet 与 opus 通过率相当（97 vs 96），单条成本是 opus 的 19%（省 81%），耗时少约四成；haiku 再省一半但掉到 88，主要错在「四个人 / 四张」这类参与人表达没读出来。据此把录入解析的默认模型切到 sonnet（`lib/claude.ts` 的 `EXTRACT_MODEL`，2026-11-10 生效）；核账 Agent、检索、报告、导入没做过同样的评测，默认保持 opus。

## badcase 归类（基线三模型共 34 处错误）

| 类别 | 处数 | 占比 | 例子 |
|---|---|---|---|
| 请客语义 | 10 | 29% | 「小林请客，奶茶四杯」没把被请的人列全就追问；「这顿他来」没识别为请客；「老王请我们」判成非消费 |
| 该追问却自动入账 | 9 | 26% | 「地铁 4 块，我和阿强」没说谁付，默认成「我」；一句里两笔消费直接入账 |
| 该入账却追问 | 9 | 26% | 「我自己买了件衣服」参与人留空；haiku 把「四个人」漏掉 |
| 字段错 | 4 | 12% | 「买单…她请」分类成其他；语音同音「小花」 |
| 误判为非消费 | 2 | 6% | 押金、非成员代付 |

## 这一轮修了什么（只改提示词 `lib/extract/prompt.ts`，不改代码）

1. 请客触发词从「请客 / 我请 / X 请大家」扩到「这顿我来 / 算我的 / 买单不用 AA / 不用分」；没点名被请的人时默认全体成员减付款人；「X 没吃 / 没来」再去掉 X；请客时的参与人置信度给法写明（说了大家或列了名单 0.9，只说请客 0.8）。
2. 付款人不在成员名单（老王、导游、店家）：仍是消费，payer 为 null 并追问要不要加成员，不判非消费。
3. 文字 / 语音没说谁付：payer 为 null 并追问，不默认当前使用者（只有支付截图才默认）。
4. 「自己的 / 自己用」：参与人只有付款人；「我们 / 大家」永远指全体成员，与付款人是谁无关。

效果：请客类错误 10 → 2；sonnet 90 → 97、opus 92 → 96、haiku 84 → 88；原 20 例 sonnet 18 → 20、haiku 16 → 19、opus 持平 18 → 19，没有回退。

## 还没修的（after 仍错的 19 处）

- 该入账却追问 8 处（42%），主要是 haiku 对「四个人 / 四张」的参与人表达，下一轮的目标。
- 一句两笔（c74）三个模型都直接按第一笔入账，需要在 schema 里允许多笔或明确追问。
- 「买单…她请」没有食物词时分类成其他（c95），语音同音「小花」付款人留空（c40），属于标注边界，可接受。

## 边界

- 评测集是自己构造、自己标注的，没有第二个人复核，也没有线上真实分布；「用户试用」这一步（飞轮第 4 步）没做。
- 每个模型每轮只跑一遍，没有重复采样，1–2 例的差距在噪声范围内；模型之间 4–9 例的差距和 5 倍成本差是可信的。
- 结果文件在 `eval/results/`（不入库），可用 `npm run eval -- --label xxx` 复现。
