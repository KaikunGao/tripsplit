# 核账：固定流程对 Agent 循环的对照评测（2026-11-13）

结论先说：用 Opus 时，固定流程和 Agent 循环查出的问题一样多（两遍合计都是 123/124），固定流程每本账便宜约两成、快一成，所以默认实现改成固定流程。用 Sonnet 时 Agent 循环更好（97% 对 92%，误报 0 对 9）。汇总表全文在 `评测-核账-2026-11-13-汇总表.md`（脚本生成）。

## 为什么做

核账原来是一个 Agent 循环：模型自己决定调哪些只读工具，最后提交结论。线上唯一一次运行记录是 2 轮、5 个工具各调一遍后提交，和固定流程没有区别。简历和作品集上写的理由是「核账要查什么事先不固定，才用 Agent」，这句话没有证据。

## 两种做法

| | 固定流程（`lib/agent/pipeline.ts`） | Agent 循环（`lib/agent/run.ts`） |
|---|---|---|
| 谁决定调什么 | 代码：规则体检、查重、分类统计、结算预览四项检查加全部账目，一次交给模型 | 模型：7 个只读工具，自己决定调哪些、调几轮 |
| 模型调用 | 1 次 | 2 到 3 轮 |
| 判断规则、输出结构 | 同一份（`JUDGE_RULES`、提交工具的 JSON Schema） | 同一份 |

对照比的只是「谁决定调什么」，提示词里的判断规则、字段说明、枚举都是同一份。

## 评测集

12 本构造账本（小 4、中 5、大 3，其中两本是干净的），380 笔。埋了 62 处问题：规则检查能直接命中的 23 处，账面和自己的原话矛盾的 25 处，要靠判断的 14 处。另有 110 处「看着可疑其实没问题」的干扰项，分 12 类。全部是构造的，没有一本来自真实出行。

评分：一条结论算查出某个问题，要求它列的账目至少一半落在这个问题里；列了 3 个以上不相干账目的另记一条误报。不调模型的基线：

| 基线 | 查出 | 误报 |
|---|---|---|
| 纯规则（把规则体检和查重的命中原样当结论） | 23/62 | 27 |
| 只看表面特征猜（来源、置信度、固定字眼、同名同额） | 非规则类 0/39 | — |
| 每本账只交一条、列出全部账目 | 0/62 | 12 |

## 第一轮为什么作废

第一轮（12 本、51 处问题）跑完后请独立的一遍复查，发现结果不能用：

- 账本泄露答案。只看来源和置信度的取值就能零误报猜中 25/51，加上固定字眼和同名同额能猜中 46/51，没有表面线索的问题只剩 5 处。
- 同一条备注跨天重复（两天都是同一张门票）、两个人的账用了全员的金额，这些本身就像问题，模型报出来却被记成误报。
- 误报里混着三种东西：模型在说「这不是问题」、生成器自己造的疑点、真误报。
- 查出只看账目编号有没有交集，一条列了全部账目的结论能拿满分。

于是重做了账本生成器和评分器，加了上表三条基线做自检，提示词补了四条规则（原话逐项对照、判断为正常的不写成结论、没依据不给具体修改值、删重复时留哪条），两种做法同时改。第一轮的数字不再引用。

|---|---|---|---|---|---|---|---|---|
| 纯规则 | 23/62 | 23/23 | 0/25 | 0/14 | 8/42 | 27 | — | — |

## 怎么读

- **Opus：两种做法没有差别。** 24 对「账本 × 遍」里查出数全部相同，修改建议都是 84/84，唯一没查出的是同一处（外币行程里一笔没有原话的人民币账）。固定流程的成本是 Agent 的 80%，耗时是 87%。
- **Agent 在 Opus 上确实不是走固定套路。** 24 次运行里没有一次是「六个工具各调一遍就提交」，18 次换了查重的参数，7 次逐笔查看了账目。多做的这些探查没有换来更多发现。
- **Sonnet：Agent 循环更好。** 查出 120 对 114，误报 0 对 9。固定流程的 9 条误报里 7 条是把「出发前预订」报成日期异常，提示词里明明点名说这属正常。Sonnet 一次调用里要同时消化检查结果、全部账目和七条规则，容易顾此失彼；分成两轮先看检查结果再下结论，就稳了。
- **Haiku：两种做法接近**（118 对 117），漏的集中在判断类。它的成本是 Opus 的二十四分之一。
- 模型的价值在规则查不到的那两类：纯规则 23/62，证据矛盾类和判断类一处都查不出。

## 决定

默认改成 **固定流程 + Opus**（`TRIPSPLIT_RECONCILE_MODE` 默认 `pipeline`，`TRIPSPLIT_RECONCILE_MODEL` 默认 `claude-opus-5-5`）。核账一趟旅行只跑几次，漏掉一处就会结算错，所以按查得全来选；在查得一样全的前提下选更简单、更便宜的那个。Agent 循环的代码留着，设 `TRIPSPLIT_RECONCILE_MODE=agent` 可以切回去。

如果以后要压成本：Agent + Sonnet 是 97%、每本 4 美分；固定流程 + Haiku 是 95%、每本 0.3 美分。

## 复查顺带发现并改掉的

- **结算把请客算反了。** `splitOf` 没有读请客标记，被请的人平摊了全款，单测断言的也是错的那种。改成请客时全额由付款人承担，补了「垫付」和「请客」两条测试。
- 分类统计把不同币种的原币金额直接相加，改成折算成本币再统计。
- 成本价目表写错（另见 `评测-2026-11-10.md` 顶部的更正）。
- 固定流程在输出被截断或结构不合法时抛的是 SDK 的英文原始错误，改成自己解析、校验、重试一次，报中文提示。
- 修改建议里参与人写成人名时会被静默清空，改成不动参与人。

## 局限

- 账本全是构造的。真实账本里问题少得多，写法也不一样；模拟试用里照平时说话记的五本账，核账只报了 3 条低优先级的提示。
- 每个配置只跑两遍，Sonnet 上 120 对 114 的差距有 6 处，方向两遍一致，但不要当成精确的数。
- 提示词是看了第一轮的误报之后改的，点名的五种正常情况正好是第一轮的干扰项类型。第二轮新加了七类没被点名的干扰项，Opus 和 Agent · sonnet 在这些上也几乎没有误报，说明不全是贴着题改的；但没有一个从未见过的评测集来验证。
- 两种做法的 effort 都固定在 medium，没有试过调高以后 Sonnet 的固定流程会不会追上来。
- 示例账本「埋了 5 处异常、全部查出」的说法不再用。示例账本的账目编号本身带着答案；而且其中一处（钟水饺，阿强付、另外三人吃）按原话是替别人垫付，本来就不算错，新版核账把它判为正常。

## 怎么重跑

```bash
npx tsx scripts/eval-reconcile.ts --selftest
npx tsx scripts/eval-reconcile.ts --rules-only --label v2
npx tsx scripts/eval-reconcile.ts --mode pipeline --model claude-opus-5-5 --reps 2 --label v2
npx tsx scripts/eval-reconcile.ts --mode agent --model claude-opus-5-5 --reps 2 --label v2
npx tsx scripts/eval-reconcile-report.ts v2
```

第二轮六个配置合计花费约 5.6 美元（Opus 两个配置占 3.8 美元）；作废的第一轮约 5.5 美元。
